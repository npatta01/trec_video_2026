# Repository Hygiene and Experiment Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one canonical navigation index for dated experiment evidence and connect it to the existing project-status hub without moving, deleting, or duplicating evidence.

**Architecture:** `docs/experiments/README.md` is a static directory-level index. It routes readers to the existing dated evidence records and the six-theme status pages, but does not restate changing results or create a second next-test ledger. The three QMD status sources remain the editable report sources; their generated Markdown and self-contained HTML siblings are regenerated by the existing Quarto workflow.

**Tech Stack:** Markdown, Quarto QMD, generated GitHub-Flavored Markdown, self-contained Quarto HTML, shell-based link/diff/privacy checks.

## Global Constraints

- Preserve every existing report, experiment, artifact, plan, and generated-output path.
- Do not move or delete historical evidence, generated HTML, or plan records.
- List each dated experiment record once; treat the `.qmd`/`.md` Nemotron pair as one record and identify the QMD source explicitly.
- Keep conclusions condition-bound and link to the existing theme page instead of copying result prose into the new index.
- Edit only QMD sources by hand; regenerate sibling Markdown and `reports/project-status/*.html` through the documented workflow.
- Do not access, copy, stage, commit, or expose `data/`; this documentation task needs no dataset.
- Do not commit or publish until the scope review approves; after approval,
  stage only the named documentation and generated-report files and request
  review before merge.

```bash
guide_render_cache=$(mktemp -d /tmp/trecvid-guide-render.XXXXXX)

```
