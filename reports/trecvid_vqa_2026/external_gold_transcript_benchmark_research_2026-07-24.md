# External reference-transcript benchmark research (2026-07-24)

## Decision

Use the **Audio-Visual Lombard GRID Speech corpus** for a *four-clip plumbing
sanity check*, not for a TRECVID effectiveness claim.  It is the only examined
option that is simultaneously (a) directly downloadable at clip level today,
(b) explicitly CC BY 4.0, and (c) has a deterministic, recording-level
reference text that is not generated by ASR.  The official page describes 54
talkers, 5,400 utterances, synchronized front/side video, word alignments, and
the CC BY 4.0 release [here](https://spandh.dcs.shef.ac.uk/avlombard/).

This is a **speech-video control corpus**, not a natural-video QA benchmark.
Its six-token GRID grammar makes it excellent for detecting a broken
frames/transcript condition or a mis-bound transcript, but it cannot establish
that a transcript helps on open-domain TRECVID questions.  Keep its results
separate from the issue #7 panel and label them `external_speech_control`.

## What counts as reference here

The recommended reference is the sentence the participant was asked to say,
recorded in the corpus filename/metadata.  The corpus documentation decodes a
six-character utterance identifier (for example, `pgag6a` means “place green at
g 6 again”) and, crucially, marks mis-spoken recordings with `_WRONG` and gives
the text actually said in `TRANS` [in its format specification](https://spandh.dcs.shef.ac.uk/avlombard/).
Thus, select only records without `_WRONG`; their decoded filename is a genuine
dataset reference transcription of the recording prompt, not a machine caption
and not a multi-ASR consensus.  The supplied alignment files are timing aids,
not the source of the words.

This is not a blind, post-hoc human transcription.  That limitation must remain
visible in provenance: call it `dataset_recording_prompt_reference`, never
`human_verified_oracle`.  If a malformed/`_WRONG` record is ever used, the
`TRANS` value (rather than the target filename code) is the only admissible
reference; for the tiny protocol below, simply exclude it.

## Exact tiny protocol: four official Lombard GRID samples

This is intentionally a **smoke test** (four media items, twelve requests),
not a significance test.  It tests that all three conditions keep visual input
identical and that a known reference is routed only into the intended condition.

### Fixed media and reference table

Fetch only these official synchronized *front-video* and *audio* sample URLs,
record their SHA-256 values, and preserve the original filenames. All eight
are linked by the corpus’s sample table
[here](https://spandh.dcs.shef.ac.uk/avlombard/).

The source text is decoded only from the corpus’s documented codebook: `s/g/b/e/5/s` = set/green/by/e/5/soon and `b/g/a/h/2/n` = bin/green/at/h/2/now.  Do not “correct” its case, punctuation, or wording using ASR.  The two plain/Lombard pairs intentionally have the same lexical target but different recordings, which makes an audio-condition wiring mistake easy to see.

### Execution and freeze order

1. Download the four synchronized `.mov`/`.wav` pairs and validate HTTP
   success, filename, file hash, decodability, and matching duration. The sample
   `.mov` files are video-only; use the paired corpus `.wav` files for ASR.
   Store no dataset artifact in Git.
2. For each file, determine decoded duration and choose exactly 12 chronological
   frame timestamps at `duration * i / 13` for `i=1..12`.  Decode them once to
   PNG (or the runtime’s fixed image representation), hash them, and reuse the
   same ordered frame paths/hashes in **all three** requests for that `video_id`.
3. Run the configured automatic ASR exactly once on that frozen file/audio with
   its model revision, runtime image, language detection, output text, timestamps,
   and hashes captured.  It must receive no reference text.  This is the
   `frames_automatic_transcript` transcript even if it happens to match the
   reference perfectly.
4. Construct three requests per `video_id` with the same prompt, model revision,
   decoding, seed, 12 frame hashes, and media hash:

   | condition | transcript field |
   | --- | --- |
   | `frames_only` | absent / `null` |
   | `frames_automatic_transcript` | frozen ASR output only |
   | `frames_dataset_reference` | the table’s corpus reference only |

5. Freeze all twelve predictions before loading answer labels.  Then report (a)
   per-item answer accuracy, (b) automatic-ASR WER against the corpus reference,
   and (c) the three condition deltas.  Report the raw four-item table; do not
   attach a confidence interval or make a general-performance claim.

### Guardrails

- The reference is a dataset-provided recording-prompt reference, not a human
  transcriber/reviewer record.  It must **not** be passed through a validator
  that claims `human_verified_oracle`; add a separate, explicit provenance tier
  if the current contract only accepts human review.
- Do not call uploader captions, an ASR ensemble, or a transcript selected by
  agreement among ASR systems “gold.”  Neither is used above.
- Keep answers and any TRECVID labels out of transcript-production and request
  construction.  The question/answer scoring table is loaded only after the
  complete three-condition prediction freeze.
- Do not redistribute the clips in the report, Git, or public artifacts.
  Retain the original corpus attribution and CC BY 4.0 notice with any local
  derived frame bundle.

## Escalation path

If the four-item smoke test works, use a **single** Lombard GRID talker package
(front video ≈17.8 MB plus alignment ≈47.5 KB was checked for talker 2) and
select 12 sorted, non-`_WRONG` recordings with distinct utterance codes and a
balanced plain/Lombard mix.  This remains a controlled speech diagnostic.  Do
not switch to LRS3 until an official, legally valid, downloadable source is
restored; do not switch to MuAViC unless a project explicitly authorizes the
multi-gigabyte mTEDx/YouTube acquisition and its upstream terms.
